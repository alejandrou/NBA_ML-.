# Goal

Expose the first read-only team resources: `GET /api/v1/teams` and
`GET /api/v1/teams/{team_id}`, built on a dedicated read-only query repository,
explicit Pydantic schemas, a service layer, and an HTTP router.

# Acceptance criteria

- Only the two GET routes are added.
- The repository receives an existing Session and never creates, closes, commits,
  flushes, mutates, or returns a Session.
- The API does not use `CoreRepository`.
- Responses expose only the approved fields and never serialize ORM objects.
- Missing teams return 404; invalid path or pagination inputs return 422.
- Valid empty pages return 200 with `items: []`.
- Repository, service, HTTP, and OpenAPI tests are offline and deterministic.

# Scope

`src/nba_data/api/{app,routers/teams,schemas/teams,services/teams}.py`,
`src/nba_data/db/repositories/queries/teams.py`, and the three matching unit
test modules.

# Out of scope

Aliases, seasons, rosters, players, statistics, nested relationships, name or
abbreviation or franchise or season filters, write routes, model changes,
migrations, scraping, live database requirements.

# Implementation notes

Public team contract:

- `team_id: int` — the internal `core.teams` identifier
- `basketball_reference_team_id: str | null`
- `current_abbreviation: str | null`
- `current_name: str`
- `franchise_id: str | null`

List parameters `page: int = 1`, `page_size: int = 50`, `page_size <= 100`.
Order by `current_name ASC, team_id ASC`.
