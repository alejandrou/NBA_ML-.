# Goal

Integrate SQLAlchemy lifecycle ownership into the FastAPI app without adding
data-query endpoints.

# Scope

Create one Engine and one sessionmaker per FastAPI app instance during lifespan,
store app-owned resources on `app.state`, provide one caller-owned Session per
request through an overrideable dependency, and dispose the Engine on shutdown.

# Acceptance criteria

- `GET /api/v1/health` still returns exactly `{"status": "ok"}`.
- Health does not create or request a database Session.
- Each app instance owns an independent Engine and sessionmaker.
- Each request that uses the dependency receives an independent Session.
- Request Sessions are always closed after the request.
- The Engine is disposed during app shutdown.
- The dependency never commits, rolls back hidden writes, creates an Engine, or
  returns a sessionmaker.
- Dependency overrides continue to work in tests.
- Tests use fakes or mocks and do not connect to PostgreSQL.

# Constraints

Do not add team or season endpoints, query repositories, schemas, services,
database model changes, migrations, scraping, readiness checks, or real database
connections. Reuse `create_db_engine()` and `create_session_factory()` once per
app; do not call the current `get_session()` dependency directly from the API.
