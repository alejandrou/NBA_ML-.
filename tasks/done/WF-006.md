# Goal

Separate "not ready to start" from "ready to start" in the task lifecycle, and make
the lifecycle invariants machine-checkable instead of a prose checklist.

This card is a **record written after the fact**. The work predates the
`tasks/planning/` stage it introduces, so it never travelled the lifecycle itself.
It is kept here so `tasks/done/` tells the complete story of the workflow series.

# Evidence and current state

After WF-001…WF-005, `tasks/backlog/` meant two things at once: the living roadmap
*and* the queue of startable work. A vague idea and a fully specified task sat in the
same folder, and `Start the next task.` could not tell them apart — the difference
lived only in prose the selector never reads.

The lifecycle rules themselves were enforced by hand. The previous 216-line
`scripts/harness/` validator had been removed with the pointer workflow and nothing
replaced it.

# What changed

- **`tasks/planning/`** added ahead of `backlog/`. A card stays there while it needs
  research, a decision from the owner, resources, splitting, or while its acceptance
  criteria or validation commands are unknown. `backlog/` now holds only work that
  can be started immediately, and remains the roadmap.
- **`.agents/skills/plan-task/`** — `Plan this task: <description>` researches one
  named idea and writes a card into `planning/`.
- **`.agents/skills/prepare-task/`** — `Prepare <TASK-ID> for implementation.`
  resolves the unknowns and promotes the card to `backlog/`, or stops and reports
  what only the owner can decide.
- **`scripts/validate_tasks.py`** — standard library only, offline, ten checks
  (single in-progress card, unique ids within and across stages, required and
  forbidden frontmatter fields, dependency resolution, resolved decisions in
  `backlog/`, `active/` dependencies done, filename matches id, lifecycle folders
  present). `start-task`'s hand-written integrity list was replaced by a pointer to
  it.
- **`tests/unit/test_validate_tasks.py`** — 33 unit tests, including one that runs
  the validator against the real `tasks/` tree. `uv run pytest` already runs in CI,
  so the lifecycle is enforced without a second pipeline and without touching
  `.github/workflows/ci.yml`.
- **Knowledge preserved from the deleted `specs/`**:
  `docs/validation/PLAYER_PAGE_CACHE_ACQUISITION.md` (F4E-010's operational scraping
  rules as a runbook), the loader natural-key registry appended to
  `docs/architecture/SYSTEM_DESIGN.md`, and the Peewee removal gate appended to
  ADR 0002.
- **`docs/architecture/IMPACT_MAP.md`** — on-demand index answering "if I change
  this, what else must I check?", recording the cross-file couplings that previously
  existed only as tribal knowledge.
- ADR 0017, `AGENTS.md`, `README.md`, `tasks/README.md`, `.agents/index.md` and the
  four existing skills updated to describe five stages consistently.

# Impact

Documentation and workflow only. No product code, no schema, no migration, no
scraping. Every runtime approval interlock (`--owner-approved`,
`--execute-approved-*`) is untouched.

## Manual sad path

A copy of `tasks/planning/F4E-011-*.md` placed in `tasks/backlog/` was rejected by

never dirtied.

## Known limitations

- The frontmatter parser accepts a deliberate YAML subset (`key: scalar`,
  `key: []`, and block lists). Anything else is reported as an error rather than
  guessed at. There is no YAML dependency in this project.
- No check enforces a non-empty `validation:` in `backlog/`; that stays a
  `prepare-task` instruction.
