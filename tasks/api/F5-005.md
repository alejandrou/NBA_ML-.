# Goal

Review and close the initial read-only API resource block covering lifecycle,
teams, and seasons.

# Scope

Inspect the completed F5-002 through F5-004 work for contract compliance,
layering, read-only query boundaries, OpenAPI output, pagination, errors, and
offline tests. This task does not add new API functionality.

# Acceptance criteria

- Only approved GET routes exist.
- Health does not use the database.
- Database resources use one app-owned Engine, one app-owned sessionmaker, and
  one request-scoped Session.
- The API does not use `CoreRepository`.
- API query paths do not call `add`, `add_all`, `flush`, `commit`, `delete`, or
  `merge`.
- Counts occur after filters and before pagination.
- Every list query has deterministic ordering.
- Schemas do not expose ORM objects directly.
- API code does not import scraping.
- HTTP tests do not require PostgreSQL.
- No player, statistic, mutation, ranking, OVR, similarity, ML, or frontend work
  is introduced.
- OpenAPI contains only the approved routes.
- Declared validation passes.

# Constraints

Do not broaden Phase 5 beyond the initial lifecycle, teams, and seasons block.
Plan the next API block separately after this review closes.
