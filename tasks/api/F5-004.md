# Goal

Implement the first read-only season resources after the public season contract
is approved.

# Scope

Expose only `GET /api/v1/seasons` and `GET /api/v1/seasons/{season_year}` using
a dedicated read-only query repository, explicit Pydantic schemas, a service
layer, and an HTTP router.

# Public contract to approve

Initial season responses use `season_year` as the public identifier. The domain
meaning is that `season_year = 2024` represents the 2023-24 season.

Season response fields:

- `season_year: int`
- `league: str`
- `label: str | null`

Initial scope is NBA only with `league = "NBA"`. Order by
`season_year DESC, league ASC`.

# Acceptance criteria

- Only the two approved GET routes are added.
- The repository receives an existing Session and never creates, closes, commits,
  flushes, mutates, or returns a Session.
- The API does not use `CoreRepository`.
- Responses expose only the approved fields and never serialize ORM objects
  directly.
- Missing seasons return 404; invalid path or pagination inputs return 422.
- Valid empty pages return 200 with `items: []`.
- Repository, service, HTTP, and OpenAPI tests are offline and deterministic.

# Constraints

Do not expose the internal season ID, add public multi-league support, add
players, teams-by-season, statistics, write routes, model changes, migrations,
scraping, or live database requirements.
