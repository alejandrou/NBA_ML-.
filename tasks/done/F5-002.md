# Goal

Give the FastAPI app ownership of the SQLAlchemy lifecycle without adding any
data-query endpoints: one Engine and one sessionmaker per app created during
lifespan, one caller-owned Session per request via an overrideable dependency,
and Engine disposal at shutdown.

# Acceptance criteria

- `GET /api/v1/health` still returns exactly `{"status": "ok"}` and creates no
  Session.
- Each app instance owns an independent Engine and sessionmaker.
- Each request using the dependency receives an independent Session, always
  closed after the request.
- The Engine is disposed during app shutdown.
- The dependency never commits, hides writes, creates an Engine, or returns a
  sessionmaker.
- Dependency overrides continue to work in tests.
- Tests use fakes and never connect to PostgreSQL.

# Out of scope

Team or season endpoints, query repositories, schemas, services, model changes,
migrations, scraping, readiness checks, real database connections.

# Implementation notes

Reuse `create_db_engine()` and `create_session_factory()` once per app. Do not
call the module-level `get_session()` dependency from the API — it creates an
Engine per call.
