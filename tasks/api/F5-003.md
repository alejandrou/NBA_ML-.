# Goal

Implement the first read-only team resources after the public team contract is
approved.

# Scope

Expose only `GET /api/v1/teams` and `GET /api/v1/teams/{team_id}` using a
dedicated read-only query repository, explicit Pydantic schemas, a service layer,
and an HTTP router.

# Public contract to approve

Use the internal integer `core.teams` identifier as `team_id` and also expose
`basketball_reference_team_id`.

Team response fields:

- `team_id: int`
- `basketball_reference_team_id: str | null`
- `current_abbreviation: str | null`
- `current_name: str`
- `franchise_id: str | null`

List parameters are `page: int = 1` and `page_size: int = 50`, with
`page_size <= 100`. Order by `current_name ASC, team_id ASC`.

# Acceptance criteria

- Only the two approved GET routes are added.
- The repository receives an existing Session and never creates, closes, commits,
  flushes, mutates, or returns a Session.
- The API does not use `CoreRepository`.
- Responses expose only the approved fields and never serialize ORM objects
  directly.
- Missing teams return 404; invalid path or pagination inputs return 422.
- Valid empty pages return 200 with `items: []`.
- Repository, service, HTTP, and OpenAPI tests are offline and deterministic.

# Constraints

Do not add aliases, seasons, rosters, players, statistics, nested relationships,
name filters, abbreviation filters, franchise filters, season filters, write
routes, model changes, migrations, scraping, or live database requirements.
