# Goal

Expose the first read-only season resources: `GET /api/v1/seasons` and
`GET /api/v1/seasons/{season_year}`, using a dedicated read-only query
repository, explicit Pydantic schemas, a service layer, and an HTTP router.

# Human decisions or resources

- None.

# Acceptance criteria

- Only the two GET routes are added.
- The repository receives an existing Session and never creates, closes, commits,
  flushes, mutates, or returns a Session.
- The API does not use `CoreRepository`.
- Responses expose only the fields below and never serialize ORM objects
  directly.
- The internal season ID is never exposed.
- Missing seasons return 404; invalid path or pagination inputs return 422.
- Valid empty pages return 200 with `items: []`.
- Repository, service, HTTP, and OpenAPI tests are offline and deterministic.

# Scope

`src/nba_data/api/app.py`, `src/nba_data/api/routers/seasons.py`,
`src/nba_data/api/schemas/seasons.py`, `src/nba_data/api/services/seasons.py`,
`src/nba_data/db/repositories/queries/seasons.py`, the three matching unit test
modules, and `docs/architecture/API_CONTRACT.md`.

# Out of scope

The internal season ID, public multi-league support, players, teams-by-season,
statistics, write routes, model changes, migrations, scraping, live database
requirements.

# Impact

Adds one router, one schema module, one service, and one query repository to the
`api` flow in `docs/architecture/IMPACT_MAP.md`. Reads `core.seasons` only — no
schema change, no migration. Extends `docs/architecture/API_CONTRACT.md` and the
OpenAPI surface asserted by the API tests.

# Implementation notes

Public season contract:

- `season_year: int` — the public identifier; `2024` means the 2023-24 season
- `league: str`
- `label: str | null`

Initial scope is NBA only, `league = "NBA"`. Order by
`season_year DESC, league ASC`.

Follow the layering established by F5-003 (teams), which is merged in `main`:
`src/nba_data/api/{routers,schemas,services}/teams.py` and
`src/nba_data/db/repositories/queries/teams.py` are the reference
implementation. The `queries/` package already exists — add `seasons.py` to it
rather than recreating it.
